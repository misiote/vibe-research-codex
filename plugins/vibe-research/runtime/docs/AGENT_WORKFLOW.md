# Coding Agent / 使用者接力约定

1. 从 `vr status`、`vr tree`、`vr gaps`、`vr reading queue` 恢复上下文；对相关论文、代码、结果使用 `vr trace ID`。
2. 将用户研究语言转为可审查的节点与边。所有图和状态更新通过 `vr`，禁止直接修改 `.research` 的库/快照/审计记录。
3. `vr search ... --import` 获取书目，用 `vr reading triage` 记录初筛依据。只要候选可能提供直接答案、方法、数据、基线、反证、边界或路线连接，就判为 `valuable` 并在同一轮进入系统精读；负结论、局限或观点相反不是排除理由。重复文献复用已有节点。
4. 有价值但没有全文时，先尝试合法可用的开放版本、机构访问版本或用户已有文件，并保持“待获取全文”状态。全文到位后用 `vr paper attach` 保存，再用 `vr reading packet` 获取逐页文本、质量问题和细节账本。回看 PDF 的公式、图表与实验设置。逐条提交原文、页码、解释、置信度，并记录作者主张、命题类型、证据作用、质量判断、适用范围、未决问题和复现细节；不把摘要读取标为全文精读。`quote_verified` 只说明原文匹配。
5. 使用 `vr reading review` 保存审阅结果。由谁审阅会进入 `VR_ACTOR` 审计；v0.1 不强制另一个人审阅。不要把自动审阅包装成独立人工审阅。
6. 从证据创建主张、缺口、假设；没有找到对照研究只说明检索范围内暂未发现，不足以证明研究空白。
7. 先建立实验规范，再在真实工程仓库运行。记录运行时 commit、实际配置、seeds、日志和 metrics。`vr experiment ingest` 不替代实验执行。
8. 失败要包含原因、证据、禁止重复项、复活条件。用 `vr transition` 或 `vr decide` 更新状态；用新假设节点表达修订，保留旧路线。
9. 梳理研究方向时保存来源、查询、失败、全文比例和停止理由；按问题、方法、证据、边界与时间组织路线，再把外部工作与本地研究图逐项对齐。单源成功不能写成全面覆盖。
10. 阅读报告、研究版图、实验报告、研究简报和交接文档在科学审阅后交科研写作编辑定稿。编辑可改结构和句子，不能改变证据强度、数字、引文、范围或状态。
11. 交接前运行 `vr doctor`，在回复里报告当前问题、证据、仍有疑问的结论和下一项实验。SQLite 不可跨机器直接合并；新 clone 使用 `vr db restore`。

自然语言示例：“检查增加种群规模是否只是增加计算预算”。Agent 应先检索现有路线与文献，创建带对照条件的 H 与 X，而不是直接声称已完成实验。

当前不提供内嵌 LLM 服务、MCP server 或自动研究守护进程；使用现有 coding agent 的终端执行能力。
