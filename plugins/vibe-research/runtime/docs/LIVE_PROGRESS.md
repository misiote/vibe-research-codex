# 看得懂的研究工作现场

## 用户先看到什么

先回答五个问题：这轮在解决什么；为什么值得做；最近得到什么；下一步是什么；是否需要我决定。默认不显示原始命令、SQL、JSON、令牌流、内部思考或重复心跳。技术原因在记录详情中查看，完整工具输出留在 Codex 原生工具视图。

当前工作与科学成果分开：工作报告是助手的说明，工具记录表示命令已返回，右侧产出数字才来自实际研究库。归档全文不能冒充精读完成，计划不能冒充结果。不给整个研究虚构百分比或预计完成时间。

## 打开动态页面

```bash
vr --project /你的研究目录 watch
```

打开命令显示的本机地址（默认 http://127.0.0.1:8765）。服务运行时每 2 秒更新；页面可以放在 Codex 右侧，也可以用浏览器打开。端口被占用可使用 `--port 8766`。保持服务运行，Ctrl+C 停止；重新运行可读到上次工作记录。

点击关联产物，在同一页面展开 Wiki 关系图并定位到对应节点。图只在研究版本变化时更新，不随每次轮询重置。过程记录默认显示最近 8 条，可展开到最近 60 条；暂停显示更新不暂停助手执行。

超过 2 分钟没有工作更新会显示“状态待确认”，不推断失败或仍在运行。服务断开保留最后记录并显示断开提示，自动重试。

## 助手的过程协议

开始工作时用一句可读目标和目的建立工作记录。返回的 W 标识用于后续更新：

```bash
vr work start --title '核对 DanZero 的观测编码' --why '避免把不可见信息送入策略模型' --next-step '先定位论文方法段落' --nodes P0001
vr work update W标识 --message '已找到观测说明，正在核对历史信息的范围' --next-step '对照实现中的字段' --nodes P0001
vr work update W标识 --state waiting --message '原文接口暂时限流' --next-step '稍后重试公开镜像'
vr work update W标识 --state blocked --message '两份规则说明的回合结束条件不同' --next-step '确认版本后继续核对' --needs-user '这次实验采用哪个规则版本？'
vr work finish W标识 --message '已保存三条待审阅证据' --next-step '审阅解释后再设计对照实验' --nodes V0001 V0002 V0003
```

上述是语法示例，节点和 W 标识必须替换为当前项目实际值。失败结束用 `work finish ... --state failed`；结束时仍说明留下的结果和下一步。`work status` 恢复上下文，每个项目同时只保留一项未结束工作，避免两个助手互相覆盖状态。

仅在目标变化、有新发现、产出保存、遇到阻碍、需要决定、工作结束时写进展。确实正在等待一个长操作时，可通过 `vr work heartbeat W标识` 更新在线时间；不得脱离实际执行启动永久心跳。心跳不新增过程消息。

重要 CLI 操作会自动留下成功/失败记录；只读查看和重复状态查询不刷屏。助手在 CLI 以外阅读、搜索、写代码的活动，需要主动用 `vr work update` 汇报有意义的进展。本工具不自动监听所有 Codex 调用、不控制 Codex 原生工具卡片，也不会读取内部思考。需要用户决定时仍在 Codex 对话中提问并接收回答，页面不能授权或代替回答。

## 数据与运行范围

研究图仍由既有数据库、nodes/branches 快照管理。工作记录独立保存在 `.research/activity.db`，通过 CLI 写入；它不是研究证据，不增加研究 revision，也不随研究库 `db backup/restore` 迁移。需要迁移过程记录时在停止写入后备份该 SQLite 库及其 WAL，或使用 SQLite backup API。

服务只监听 127.0.0.1，检查 Host，不提供目录浏览、任意文件、命令执行、写入接口或跨站 API 访问。页面显示的目标/进展文字由助手提供，仍需避免写入密钥或敏感原始日志；工具自动记录只保存白名单动作与节点标识。它服务当前用户的本机工作，不是多用户远程服务。
