# 专家交接契约

任务包使用 Markdown 或 JSON 即可，不要求建立另一套研究数据库。

必备内容：
- 项目根目录、vr 启动器、协议路径、所属工作标识。
- 稳定任务名、任务版本、本次尝试、具体职责与结束条件。
- 原始输入路径、sha256、读取范围、关联研究节点和当前 revision。
- 独立输出目录、交付文件名、允许的工具/运行范围及已授权资源；未知预算写未知，不捏造额度。
- 上游依赖、已知失败、未决问题和回报给主会话的方式。

输出目录示例：工作区 `work/research-team/<工作>/<任务>/attempt-01/`。这是提案目录，不是正式研究事实库；主会话不得将迁移包/临时验证项目误认为用户当前项目。

交付至少包括：实际完成范围、输入版本、产物路径及哈希、发现与依据、未验证事项、失败/阻碍、建议动作。只有文件真实存在才报告“已落盘”。报告不携带原始内部思考，也不披露密钥。

检索主会话运行 → 专员精读 + 分析师基于已核验材料建模可分阶段开展；工程师运行结束并得到真实输出后，分析师统计；独立审查员对当前版本审查；团长记录决策与下一步。过程严格取决于材料，而非固定举行五人轮流发言。

恢复时比较当前输入与交付声明的哈希，核对已入库附件及工作历史。旧尝试已经交付但回执丢失时先查库，再决定是否补提交。无法确定状态时记录待确认，不承诺 exactly-once，不自动重跑训练。
