# Vibe Research 演示

这是同一工作区内的自然语言入口，不是后台自动运行服务。

## 默认演示

用户未指定题目时使用已有掼蛋资料，聚焦“动作表征是否会混淆牌张相同但决策语义不同的动作”。这是待核查的问题，不预设缺陷确实存在。默认完成文献取证、方案、反例复核和下一步验证设计；不运行训练，不启用付费来源。用户另有授权/目标时按其范围调整。

## 准备现场

从工作区根解析 outputs/vibe-research/bin/vr、outputs/projects.json 和 outputs/open-workbench.py。先读项目登记和工作历史。用户要求继续已有 demo 时恢复对应项目；第一次演示或明确要求重新演示时，在 outputs/demos 下创建独立且不覆盖已有目录的项目，用 vr init 和 hub add 登记为清楚标注“演示”的项目。具体命令先看 --help，不直接构造 .research 数据。

现有正式项目 outputs/guandan-research 可作为只读素材源。通过现有 CLI 导出/导入书目并附加已归档全文；不复制活动数据库，不继承旧工作的“正在进行”状态。复用论文注明来自已有材料，不能当作本轮新检索。源项目不存在或没有全文时，先使用已登记且适合的资料；必要时只问缺失的课题/资料，不要求用户重写演示流程。

项目初始化后立即启动/复用固定工作台，在宿主浏览器打开登记返回的 demo 项目地址。由主会话创建演示工作记录。遵守连续性 skill，普通恢复不新建项目。

## 真实演示流程

按专家协作 skill 实际分派文献专员读取相关全文、分析师提出可检验方案，随后由独立审查员检查当前版本的证据和反例。任务范围保持紧凑，不为展示凑齐全部五角色。没有子代理能力时明确说明，不能模拟专家发言或声称完成独立复核。

用 work update 展示实质进展，主会话通过 vr 将实际产物和证据关系入库。只复用原文全文时不假装演示了网络访问；用户要求联网时再按已有检索规则执行，保留限流/缓存说明。

完成后在 demo 项目留下可打开的总结附件：研究问题、原文证据、表征建议、审查发现、未决事项与下一步实验。关系图应能打开原文、精读记录、方案和审查产物。所有结论维持真实证据强度，演示报告不直接成为验证结果。

交付时保持工作台打开，并简短引导用户依次看：工作现场 → 研究地图 → 原文与精读 → 总结。标记实际工作完成或阻塞；不要永久维持加载动画。用户仅要求观看演示时，不改动原研究库、不启动下一轮研究。
